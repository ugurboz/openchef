# R1.2 — Spike S2: Linux Landlock + seccomp (+ S5 keep-awake on Linux)

| Owner | Milestone | Depends on | Size |
|---|---|---|---|
| Lead | R1 | R0.1 | M |

## Goal

Decide how `openchef-sandbox` enforces §21.3 on Linux: Landlock ABI levels and kernel
coverage, a seccomp deny list, behaviour where unprivileged user namespaces are
restricted, and what happens without Landlock. Experiments run in GitHub Actions
(`ubuntu-latest`, `ubuntu-22.04`, `ubuntu-24.04-arm`) and, for the agent CLIs, a Linux VM.

## Scope

`spikes/linux-landlock/` (a small Rust harness, not in the workspace),
`.github/workflows/spike-linux.yml` (manual dispatch only),
`docs/research/s2-linux-landlock.md`.

## Experiments

1. Harness: `pre_exec` applies Landlock (read-only system, read-write worktree +
   temp, nothing else under `$HOME`) and seccomp (deny `ptrace`, `mount`, `bpf`,
   `kexec_*`, `init_module`, `keyctl`, `unshare` of user ns), then execs the target.
2. Same secret-read / outside-write / inside-write checks as S1.
3. Landlock ABI reported per runner kernel; `truncate`/`ioctl`/network rules by ABI.
4. `unshare(CLONE_NEWUSER)` on Ubuntu 24.04 with the AppArmor restriction: result.
5. Each agent CLI (in a VM with logins) under the harness: minimum extra paths.
6. Verification commands and cache paths, as S1.6.
7. No Landlock (kernel < 5.13 or disabled): detection and fail-closed behaviour.
8. S5: `systemd-inhibit --what=idle:sleep` behaviour; what `doctor` can detect.

## Acceptance criteria

- [ ] Findings per experiment; recommended policy and fallback for R4.6.
