# R0.8 — `cargo-dist` release dry run in CI

| Owner | Milestone | Depends on | Size |
|---|---|---|---|

## Goal

Prove from the first weeks that `openchef` can be packaged for macOS (arm64, x86_64),
Linux (x86_64, arm64) and Windows (x86_64) with checksums, without publishing anything.

## Read first

`AGENTS.md`, `docs/architecture.md` §15 (supply chain), §19 (R8). Go reference:
`../openchef-go/.goreleaser.yaml` and the `release-check` job in `.github/workflows/ci.yml`.

## Scope

- `dist-workspace.toml` (or `[workspace.metadata.dist]` in the root `Cargo.toml` —
  only that table)
- `.github/workflows/release.yml` (generated by `cargo dist init`, then trimmed)
- `.github/workflows/ci.yml` — only a new `release-plan` job

## What to build

1. `cargo dist init` for the `openchef` binary only; targets above; installers:
   shell + PowerShell + Homebrew formula **generated but not published**.
2. CI job `release-plan` on PRs: `cargo dist plan` and `cargo dist build
   --artifacts=local` for the host target, uploads nothing.
3. The tag-triggered `release.yml` stays, but publishing steps are disabled until R8
   (`publish-jobs = []`), with a comment.

## Acceptance criteria

- [ ] `release-plan` job green on a PR.
- [ ] On your Windows machine, `cargo dist build` produces a `.zip` with `openchef.exe`
      that runs `openchef version`. Paste the output in the PR.
- [ ] No secrets or tokens added anywhere.
