## Goal

The `openchef` binary's command structure, plus the first three working commands:
`openchef version`, `openchef doctor` (detects installed agent CLIs, their versions and
login state) and `openchef init` (writes a first `config.toml` from what it finds).

## Read first

- `AGENTS.md`, `docs/architecture.md` §12.1, §13.
- Go reference (`../openchef-go`): `cmd/openchef/main.go`, `internal/cli/root.go`,
  `version.go`, `doctor.go`, `init.go`, `doctor_init_test.go`, `cli_test.go`;
  `internal/doctor/doctor.go` + test; `internal/buildinfo/*`.

## Scope

- `crates/openchef-cli/**`
- `crates/openchef-config/src/doctor.rs` (detection logic lives in the config crate so
  the daemon can reuse it), `crates/openchef-config/Cargo.toml` (only if a dependency is
  needed)

## What to build

1. **clap** derive structure for the full §12.1 command list. Commands not built yet
   are present but hidden and return `error: not implemented yet (R<n>)` with exit
   code 2. No `todo!()`.
2. Global flags `--json`, `-q/--quiet`, `--home <dir>` (sets `OPENCHEF_HOME`).
3. **version**: semver, git commit, build date, target (via `build.rs` env, like
   Go `buildinfo`); `--json` prints an object.
4. **doctor**: a `Detector` with an injectable `Runner` (as in Go) that finds `claude`,
   `codex`, `agy` on `PATH`, runs their version / auth-status commands with a timeout,
   and reports `RuntimeStatus { name, path, version, logged_in, usable, problem }`.
   Human output is a table; `--json` is stable. Exit code 1 if no runtime is usable.
5. **init**: runs detection, asks which plan each account has (interactive via
   `dialoguer` — or `--plan claude=max --plan codex=plus` non-interactively), proposes
   pools/agents/tiers like Go `init.go`, explains L2 probes and asks before enabling
   them (§10.2), then writes the config with R0.6's `save`. Refuses to overwrite an
   existing config without `--force`.
