## Goal

Make the daemon, its API client and the task CLI work on Windows with the same
behaviour and tests as on macOS/Linux. Today every socket path is `#[cfg(unix)]` and
Windows returns `Unsupported`: `openchef run`, `status`, `logs`, `daemon start` and the
kill-the-daemon test do not run there.

## What to build

1. **Socket:** AF_UNIX at `paths.socket` (`%USERPROFILE%\.openchef\daemon.sock`), as
   chosen in R1.3. The listener accepts connections and hands each stream to the same
   line-delimited JSON-RPC peer the Unix code uses.
2. **Access:** only the current user may connect. Restrict the socket (or its directory)
   with an ACL that grants the user alone, the Windows counterpart of mode `0600`.
3. **Stale socket:** holding the lock, remove a leftover socket file before binding,
   exactly as on Unix.
4. **Client:** `dial` maps "no listener" / "file not found" to `Error::NotRunning`, so
   `openchef status` says the daemon is not running and `run` starts it.
5. **Shutdown:** `daemon stop`, Ctrl-C (`daemon run` in a console) and closing the
   console stop the daemon gracefully; the socket file is removed.
6. **Kill-the-daemon:** `taskkill /F` on the daemon leaves no agent process (the Job
   Object kills the tree, R0.4), and a restarted daemon finishes the task.
