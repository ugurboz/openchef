## Goal

Windows is the platform nobody has verified on a real machine yet. Answer, by
experiment: (a) do `claude`, `codex` and `agy` work on Windows the way OpenChef drives
them; (b) does a Job Object kill their whole process tree; (c) does an AF_UNIX socket
with a user-only ACL work for the daemon; (d) which Windows confinement mechanism can
enforce §21.3 on an agent process; (e) keep-awake. This decides R0.4 details, R3.3 and
R4.7.

## Experiments (in order; record every result with exact output)

**Part A — the CLIs on Windows**
1. Install and log in to each CLI (native Windows, not WSL). Record versions and how
   each is installed (npm, standalone `.exe`, winget).
2. One turn with OpenChef's exact transport per CLI (stream-json for Claude,
   `app-server` for Codex, `acp` for agy) driven from the harness over pipes.
3. **Pipe EOF:** close the child's stdin mid-turn: does each CLI exit, and how fast?
   (Same question as §17 item 2, which was answered only for macOS.)
4. Resume: does each CLI's native resume work on Windows?
5. Paths: where does each CLI keep its state/credentials on Windows (`%USERPROFILE%`,
   `%APPDATA%`, Credential Manager)?

**Part B — process trees**
6. Start each CLI inside a Job Object with `KILL_ON_JOB_CLOSE` (create suspended →
   assign → resume). Let it start a tool command (e.g. ask it to run `ping -t localhost`).
   Close the job handle / kill the harness with `taskkill /F`: is every descendant gone?
   Check with `Get-Process` and Process Explorer.
7. Does any CLI break out of the job (e.g. a helper started via a service or
   `CREATE_BREAKAWAY_FROM_JOB`)?

**Part C — daemon socket**
8. AF_UNIX socket at `%USERPROFILE%\.openchef\daemon.sock`: create, connect, send
   JSON lines in both directions from Rust (`uds_windows` or `tokio` on Windows).
9. Restrict it to the current user (file ACL); prove a second local user cannot
   connect (or describe why you could not test it). Stale socket file after a crash:
   can it be removed and re-bound?

**Part D — confinement** (measure each option against: writes only in the worktree;
no reads of `%USERPROFILE%\oc-secret.txt`; network works; the CLI stays logged in)
10. **Restricted token** (`CreateRestrictedToken` + Job Object).
11. **Low integrity level** (`SetTokenInformation(TokenIntegrityLevel)` with the
    worktree ACL'd for low IL). Note: low IL blocks writes, not reads — confirm.
12. **AppContainer** (`CreateAppContainerProfile`, capability SIDs, worktree ACL).
    Does each CLI start, reach its API, and find its login?
13. Verification commands (`npm test`, `cargo test`, `go test`, `pytest`) under the
    best option, and which caches must be writable.

**Part E — keep-awake (S5)**
14. `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)` from the harness
    while a long command runs: does the PC stay awake on power / battery / lid closed?
