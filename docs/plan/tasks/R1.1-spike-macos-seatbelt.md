# R1.1 — Spike S1: macOS Seatbelt (+ S5 keep-awake on macOS)

## Goal

Find out, by experiment on a real Mac, whether `claude`, `codex` and `agy` can run under
a Seatbelt profile that enforces the policy of `docs/architecture.md` §21.3, and write
down the exact profile that works. This decides how `openchef-sandbox` is built on
macOS (R4.5). A spike produces **facts**, not product code.

## Read first

- `docs/architecture.md` §21.3 (policy), §17 item 6 (the questions), §6.2–6.4 (how
  OpenChef starts each CLI — use the same flags).
- `docs/research/m1-findings.md` (how earlier spikes were written).
- Go spikes for the CLI flags: `../openchef-go/spikes/claude-cli`, `codex-appserver`,
  `agy-acp`.

## Scope

- `spikes/macos-seatbelt/` — shell scripts, `.sb` profiles, a tiny Rust or shell
  harness; not part of the workspace
- `docs/research/s1-macos-seatbelt.md` — the findings

## Experiments (do them in order, record every result)

Use a throwaway git repo as the "worktree", e.g. `/tmp/oc-s1/repo`, and a fake secret
`~/oc-secret.txt`.

1. **Baseline profile:** write `spikes/macos-seatbelt/base.sb` that allows process
   exec, network, reads of `/usr`, `/bin`, `/System`, `/Library`, `/opt/homebrew`,
   `/private/var/db/timezone`, the CLI's install path; writes only to the worktree and
   a private temp dir; denies the rest of `$HOME`. Run `sandbox-exec -f base.sb
   /bin/sh -c 'cat ~/oc-secret.txt; touch ~/oc-x; touch /tmp/oc-s1/repo/ok'` → the
   first two must fail, the third succeed.
2. **Each CLI under the profile:** run one real turn with the same flags OpenChef uses
   (Claude: `claude -p --input-format stream-json --output-format stream-json
   --verbose --restricted …`; Codex: `codex app-server`; agy: `agy acp --sandbox …`).
   For each, find the **minimum** extra paths needed (its state dir such as
   `~/.claude`, `~/.codex`, the agy dir; Keychain via `mach-lookup` of
   `com.apple.SecurityServer` and friends; `~/Library/Caches/...`). Write the final
   profile per CLI.
3. **Login still works:** inside the sandbox, is the CLI still logged in (subscription
   auth via Keychain or credential file)? Does a token refresh work?
4. **Nested sandboxes:** Codex and agy apply their own Seatbelt sandbox to the commands
   they run. Inside our profile, ask each to run `ls` and `touch new.txt` in the
   worktree. Does it work, fail, or silently run unsandboxed? Try with the CLI's own
   sandbox on and off. Record exact error messages.
5. **The agent cannot escape:** inside each CLI, ask it (in `bypassPermissions`-like
   mode) to `cat ~/oc-secret.txt` and to write `~/oc-escape.txt`. Both must fail by
   kernel, not by the agent refusing.
6. **Verification commands:** under the profile run `npm test` (a tiny npm project),
   `cargo test` (tiny crate), `go test ./...`, `pytest`. Which caches must be writable
   (`~/.npm`, `~/.cargo/registry`, `~/go/pkg/mod`, `~/Library/Caches/pip`)? Does
   redirecting them into the temp dir work instead (`npm_config_cache`, `CARGO_HOME`,
   `GOMODCACHE`, `PIP_CACHE_DIR`)?
7. **Profile generation:** can the profile be passed inline (`sandbox-exec -p "<profile>"`)
   with parameters (`-D WORKTREE=/path`)? Length limits?
8. **Deprecation check:** `man sandbox-exec` warning on your macOS version; does it
   still work on the newest macOS you have?
9. **S5 keep-awake (macOS):** `caffeinate -i -w <pid>` while a long command runs: does
   the Mac stay awake on power and on battery? With the lid closed? Record macOS
   version and power settings.
