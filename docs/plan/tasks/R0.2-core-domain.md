## Goal

The pure domain every other crate speaks: tasks, steps, attempts, sessions, turns and
approvals with their status enums and transition rules, ids and typed errors. No I/O.

## Read first

`docs/architecture.md` §4, §7.1; D-018, D-022. Go: `internal/task/*.go` and tests.

## Scope

`crates/openchef-core/**`

## What to build

- One `enum` per status (`TaskStatus`, `StepStatus`, `AttemptStatus`, `SessionState`,
  `TurnStatus`, `ApprovalStatus`) with `serde` string forms identical to the Go
  constants (they are stored in SQLite and shown in the CLI).
- `check_transition(from, to) -> Result<(), TransitionError>` per machine; the allowed
  edges exactly as the Go machines; `is_terminal`, `is_active`, `terminal_statuses()`.
- Entities (`Task`, `Step`, `Attempt`, `Session`, `Turn`, `Approval`, `Decision`) as
  plain structs; validation functions return typed errors.
- `TaskId` newtype with the Go id format; `Importance`, `Effort`, `Tier` enums
  (ordering derives) for later crates.
- `proptest`: no random walk of valid transitions ever leaves a terminal state.

## Acceptance criteria

- [ ] Every test in `internal/task/*_test.go` ported and passing.
- [ ] String forms round-trip through `serde_json` and match the Go values (snapshot).
- [ ] No dependency on `tokio` or any I/O crate.
