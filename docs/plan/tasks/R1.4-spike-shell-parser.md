## Goal

The permission system's security depends on splitting a shell command into every simple
command it would run (§9.2). Go used `mvdan.cc/sh`, a mature parser. Find out whether
the pure-Rust `brush-parser` gives the same answers on the whole Go test corpus, and
list every difference, so R4.1 can be built on facts.

## Read first

- `docs/architecture.md` §9.2; D-021 (parsed commands, opaque runners, redirections).
- Go reference (`../openchef-go`): `internal/permissions/shell.go` (how commands are
  split), `permissions_test.go` (especially `TestSplit` and `TestBypassCorpus`), and
  `internal/permissions/testdata/fuzz/`.

## Scope

- `spikes/shell-parser/` — its own Cargo project (not in the workspace)
- `docs/research/s4-shell-parser.md`

## What to do

1. **Extract the corpus:** every input of `TestSplit`, `TestBypassCorpus` and the fuzz
   seeds, with the Go expected output (list of simple commands with argv,
   redirections, or "unparseable"), into `spikes/shell-parser/corpus.json`. Write a
   tiny Go program in the spike dir that prints Go's actual output for each input, so
   expected values come from running Go, not from reading code.
2. **Rust splitter:** with `brush-parser`, implement `split(cmd) -> Result<Vec<SimpleCommand>, Unparseable>`
   that mirrors `shell.go`: expands `;`, `&&`, `||`, pipes, subshells, `$(…)`,
   backticks, process substitution, here-docs, function definitions; reports
   redirection targets; treats `eval`, `sh -c`, `bash -c`, `xargs`, `env`, `nohup`,
   `time`, `exec` like the Go "opaque runner" rules (D-021).
3. **Compare:** a test that runs every corpus entry through the Rust splitter and
   compares with Go's output. Produce a table: same / different / Rust unparseable /
   Go unparseable.
4. **Extra hostile cases** the Go corpus may lack: ANSI-C quoting `$'…'`, brace
   expansion, `{ …; }` groups, arithmetic `$((…))`, `coproc`, aliases, line
   continuations, Unicode lookalike characters, null bytes, very long inputs.
   Record Go vs Rust for each.
5. **Fuzz:** `cargo fuzz` (or `proptest`) for 30 minutes: no panics, no hangs.
6. **Verdict:** for every difference, choose one: *fix in our splitter*, *fail closed
   (treat as unparseable → ask)*, or *blocker (parser must be replaced)*.

## Findings document (`docs/research/s4-shell-parser.md`)

Sections: *Versions* · *Corpus results table* · *Hostile cases* · *Fuzz result* ·
*Differences and verdicts* · *Recommendation for R4.1* (brush-parser yes/no, and the
fail-closed list).
