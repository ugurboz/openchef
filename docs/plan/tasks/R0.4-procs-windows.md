# R0.4 — `openchef-procs`: Windows Job Objects

| Owner | Milestone | Depends on | Size |
|---|---|---|---|
| **İbo** | R0 | R0.3 merged | M |

## Goal

Make `openchef-procs` work on Windows with the same public API and the same tests as on
macOS/Linux. Every child runs inside a Job Object that kills the whole tree when the
last handle closes, so no agent process can outlive OpenChef.

## Read first

- `AGENTS.md` (rules), `docs/architecture.md` §5.1 and §5.3.
- The Rust API from R0.3: `crates/openchef-procs/src/lib.rs` and the Unix module.
- Go reference (`../openchef-go`): `internal/procs/procs.go`, `procs_windows.go`,
  `helper_windows_test.go`, `procs_test.go`.

## Scope (you may create or change only these)

- `crates/openchef-procs/src/windows.rs` (and `src/windows/` if you split it)
- `crates/openchef-procs/tests/**` — only `#[cfg(windows)]` additions
- `crates/openchef-procs/Cargo.toml` — only `windows-sys` feature flags

## What to build (same behaviour as the Go code)

1. **Start:** create a Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`; spawn the
   child with `CREATE_SUSPENDED | CREATE_NEW_PROCESS_GROUP`; open it with
   `PROCESS_SET_QUOTA | PROCESS_TERMINATE | PROCESS_SUSPEND_RESUME |
   PROCESS_QUERY_LIMITED_INFORMATION | SYNCHRONIZE`; `AssignProcessToJobObject`; then
   resume it (`NtResumeProcess` from `ntdll`). The child must never run outside the job.
2. **Terminate:** Windows has no SIGTERM. Graceful = close stdin and wait `grace`;
   then `TerminateJobObject`. A cancelled token skips the grace period.
3. **Drop / close:** terminate the job and close every handle exactly once; `close()`
   is idempotent.
4. **Identity:** `start_token` = process creation time from `GetProcessTimes`
   (FILETIME as `u64`). `alive` and `kill_if_alive` compare PID **and** token, so a
   reused PID is never killed. `ERROR_INVALID_PARAMETER` from `OpenProcess` = not found.
5. Every `unsafe` block has a `// SAFETY:` comment explaining why the call is sound.

## Acceptance criteria

- [ ] Every test that runs on Unix also runs and passes on Windows (except signal-only
      tests, which are `#[cfg(unix)]` with a comment why).
- [ ] `terminate_kills_grandchildren` passes on Windows: a grandchild started by the
      child dies with the job.
- [ ] Killing the test process itself (Task Manager / `taskkill /F`) leaves no child
      alive — check by hand once and describe how in the PR.
- [ ] Stress workflow (50×) green on `windows-latest`.
- [ ] Local gate (`AGENTS.md` §4) clean on your Windows machine.

## Out of scope

Unix code, the daemon, sockets, sandboxing (R1.3 / R4.7).
